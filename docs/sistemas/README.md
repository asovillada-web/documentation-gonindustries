# Sistemas implementados

Esta carpeta empieza vacía a propósito.

Cuando exista un sistema real —por ejemplo checkpoints, hazards o victoria— su documento corto debe explicar:

- qué hace;
- dónde vive en Studio;
- qué decide el server y qué hace el client;
- cómo probarlo;
- limitaciones conocidas.

No documentamos sistemas futuros como si ya estuvieran construidos.
